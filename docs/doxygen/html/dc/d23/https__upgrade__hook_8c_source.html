1/* Default no-op implementation of the optional HTTPS upgrade hook.
2 *
3 * Applications that need to take ownership of a TLS-upgraded connection
4 * (e.g. reverse-session hijacking) provide their own strong definition of
5 * cwist_https_upgrade_handler(). This stub lives in its own translation
6 * unit so the static linker only extracts it from libcwist.a when the
7 * application does not define the symbol; the weak attribute additionally
8 * keeps --whole-archive style links from failing with a duplicate
9 * definition (both ELF and Mach-O support weak definitions). This is more
10 * portable than a weak *declaration*: Mach-O has no ELF-style weak
11 * undefined symbols, and weak_import did not satisfy the Darwin linker.
12 *
13 * Return true to detach the fd/ssl from cwist so they are not closed after
